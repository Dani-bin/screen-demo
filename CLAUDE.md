## What this is

A Vue 3 + Vite **large-screen 3D visualization demo collection** (大屏 demo 合集). The routed pages are the `/home` showcase plus fifteen three.js demos (`/school`, `/city`, `/charging`, `/building`, `/energy`, `/hometown`, `/hospital`, `/waiting`, `/smart-mine`, `/smart-ranch`, `/smart-port`, `/drone`, `/smart-conveyor`, `/coal-prep`, `/mine-fire`); all use static or simulated data, call no backend and need no login (there is no auth layer). It is display-oriented: meant to run fullscreen on a wall/monitor, not a conventional CRUD admin app.

The project grew out of an emergency-management (应急) dashboard. On 2026-10-06 all of that code was removed (Baidu Map, ECharts panels, video, AI chat, login / dict flow, Pinia, Element Plus, shared components); docs under `docs/superpowers` from before that date may still mention it.

## Responsive scaling (critical to understand)

The screen scales via rem, not media queries. **Author all sizes in `px`** — they are auto-converted to `rem` at build time:

- `postcss-pxtorem` with `rootValue: 192` converts every `px` to `rem` (see `vite.config.js`).
- `amfe-flexible` sets the root font-size at runtime so the layout scales to the viewport.
- To opt a stylesheet out of conversion, name it `*no-convert.css` (the `exclude` rule in `vite.config.js`); `building/scene/map/labels.no-convert.css` uses it because CSS3D labels are already scaled with the canvas.
- Tailwind is imported for its preflight base styles; the pages are styled with hand-written SCSS, not Tailwind utility classes, but they rely on the reset, so keep the import in `src/main.js`.
- `src/assets/styles/index.scss` registers the three fonts in use (`Alimama ShuHeiTi` titles, `Source Han Sans CN` body, `DIN` numbers) and the base `html` / `body` / `#app` styles.

## Architecture

- **Entry**: `src/main.js` → imports Tailwind base, `amfe-flexible` and `index.scss`, registers the router and mounts `App.vue`. There is no store, UI library or route guard.
- **Routing**: `src/router/index.js`, **hash history**. Top-level pages are lazy-loaded views; the registered routes are `/home`, `/school`, `/city`, `/charging`, `/building`, `/energy`, `/hometown`, `/hospital`, `/waiting`, `/smart-mine`, `/smart-ranch`, `/smart-port`, `/drone`, `/smart-conveyor`, `/coal-prep` and `/mine-fire`. Default redirect is `/home`.
  - `/home` is the demo showcase homepage with two views switched by the header toggle (`?view=wall|spotlight`, last choice kept in localStorage under `home:view:v2`, default wall since 2026-10-27; the key was bumped then so old remembered spotlight choices reset once):
    `wall` (作品墙, light) = category chips + search + a scrolling 4-column card grid where the newest demo (last entry) gets a 2×2 tile;
    `spotlight` (聚焦, dark) = the current demo's preview full-screen + a scrollable, filterable catalog on the right, auto-rotating every 8 s (pauses on hover, ↑↓/←→/Enter keys).
    Its content comes only from `src/views/home/data/demos.js` (each entry needs a `category`, which drives the filter chips); to add a demo, append an entry there, register the route, then run the preview capture script (see Commands). Design drafts: `docs/design/home-v2/`.
  - `/city` is the city 3D overview page (three.js + static OSM data, no login); its geometry is generated by `scripts/fetch-osm-city.py` into `public/city/`.

    `b.run(only={...}, keep=True)` rebuilds only some objects without clearing the already-baked ones; `import tower.bake as k; k.bake(names={...})` (~2 min per variant on the M2 GPU, ~35 min total; every bake PNG is then denoised with OIDN through the compositor (`k.denoise(path)`); bake PNGs go to the git-ignored `models/tower/bake/`; to keep the MCP call from timing out, run the bake from `bpy.app.timers.register`), `import tower.export as e; e.export()` writes `public/building/tower_S.glb` / `tower_N.glb` (meshopt-compressed, loaded with `MeshoptDecoder`).
    `bakedFloors.js` picks a variant per floor from `data/building.js` (kind / occupancy) and the scene scales it by the per-floor taper and clips the top floors with the slanted roof plane; floor heights / plan rules in `floors.py` must match the constants at the top of `BuildingScene.js` (2.2 m storeys, 4.6 m podium, ×1.42 podium plan — vertical scale is compressed on purpose; slanted roof `ROOF_RISE_K` 0.44 × plan span with the high point `ROOF_HIGH` 12 m above the top floor, so the roof plane cuts through 53–58F — steeper than OSM to match the design draft).
    Floor / elevator / asset data is demo data in `data/building.js`. Dev builds expose `window.__towerScene`.
    Floor level (`scene/floor/FloorScene.js`): one detailed, baked standard office floor per tower at real storey height (3.8 m), reused for every office floor (non-office floors are greyed out in the floor strip).
    The room layout is computed by `scripts/blender/tower/plan.py` (pure Python, no bpy): `python3 scripts/blender/tower/plan.py` regenerates `data/floorPlan.js` (room polygons, glass partitions, desks, device points — do not edit by hand),
    and in Blender `import tower.detail as d; d.run()` models the floor from the same layout, `d.bake()` (~10–15 min per tower) and `d.export()` write `public/building/floor_S.glb` / `floor_N.glb`; the ceiling + light panels object `<tag>_floor_lights` only lights the bake and is not exported.
    `tower.build.run()` without `keep=True` clears the whole scene, including the floor-level objects (collection FLOOR) — rerun `d.run()` afterwards.
    Floor data (room status, environment, devices, alarms, desk occupancy) is seeded demo data in `data/floor.js`. Dev builds expose `window.__floorScene`.
    Room level (`scene/room/RoomScene.js`): one 12 × 7.2 m conference room model shared by every floor's 大会议室, built by `scripts/blender/tower/room.py` (`import tower.room as r; r.run(); r.bake(); r.export()` → `public/building/room.glb`, bake ~18 min; run the bake from `bpy.app.timers.register` so the MCP call does not time out).
    The room shell / furniture are baked (`room` texture + `room_v` vertex colours); assets are separate objects `dev_<template id>` exported with their materials and lit in real time (pickable, filtered by category); the ids must match `TEMPLATE` in `data/room.js` (template room number 3205 is replaced by the real room id). Dev builds expose `window.__roomScene`.
- **Views**: `src/views/<page>/index.vue` is the page shell; it builds its panels from `./components/*.vue`, keeps three.js code under `./scene` (no Vue dependency) and static content under `./data`. Pages share nothing with each other — each has its own header, palette and helpers.

## Auto-imports — do not hand-import these

`unplugin-auto-import` is active (`vite.config.js`):

- Vue and Vue Router APIs (`ref`, `computed`, `onMounted`, `useRoute`, …) are **globally auto-imported** — no `import` needed. Declarations live in `auto-imports.d.ts`.
- Components are **not** auto-registered: import child components explicitly.
- `auto-imports.d.ts` is generated; do not edit it by hand.
- `.eslintrc-auto-import.json` (the auto-import globals for ESLint) is also generated by `unplugin-auto-import` during dev/build; do not edit it by hand.

## Environments

- `.env.development` / `.env.production` only set `VITE_APP_ENV`; `production` switches the build `base` to `/bi/`. There is no dev proxy and no backend.
- The `BASE_PATH` env var overrides `base` (`vite.config.js`). Every push to `master` triggers `.github/workflows/deploy-pages.yml`, which builds with `BASE_PATH=/screen-demo/` and publishes to GitHub Pages at https://dani-bin.github.io/screen-demo/ (the repo's Pages source must be set to "GitHub Actions"). Assets in `public/` must be referenced through `import.meta.env.BASE_URL`, never with an absolute `/…` path, or they break under both `/bi/` and `/screen-demo/`.
- The same push also triggers `.github/workflows/deploy-server.yml`, which builds with `BASE_PATH` = repo variable `DEPLOY_BASE_PATH` (default `/`) and rsyncs `dist/` over SSH to the user's own server (a Baota / 宝塔 static site). Server details live only in GitHub Secrets (`DEPLOY_HOST` / `DEPLOY_USER` / `DEPLOY_SSH_KEY` / `DEPLOY_PATH`, optional `DEPLOY_PORT` / `DEPLOY_KNOWN_HOSTS`); with none set the workflow skips itself. The build job never sees the secrets; the upload keeps Baota's `.user.ini` / `.htaccess` / `404.html` / `.well-known`, swaps `index.html` last and keeps old hashed files in `assets/` for 30 days so long-open screens can still lazy-load their chunks. Do not use rsync `P` (protect) filters on uploaded paths: the server's patched rsync 3.1.2 treats them as excludes and aborts with "rejecting excluded file-list name" (exit 2), which is why `assets/` is uploaded in its own pass. Server, Nginx and secrets setup: `docs/deploy-baota.md`.
- Public 体验地址 for articles, videos and other promo material (公众号 / 掘金 / 抖音, `docs/articles/`): use the self-hosted server, `http://152.136.122.39:8892/#/<route>` (collection homepage `http://152.136.122.39:8892`), never the GitHub Pages URL — the user's rule since 2026-10-27, because Pages is slow in China. Keep the `http://` prefix so the plain-text address can be copied into a browser.
