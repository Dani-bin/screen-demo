# 小学三维可视化介绍页 设计文档

日期：2026-09-21
状态：已实现

## 背景与目标

在大屏项目中新增一个页面，让观众通过三维校园了解**成都市实验小学西区分校**。
与现有应急指挥业务完全独立。

## 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 三维形式 | Three.js 真三维场景 | 用户明确选择，需要可旋转、可点击 |
| 模型来源 | 程序化建模 | 无 glTF 模型、无实拍全景；有正射卫星图 + 地图矢量轮廓 + 立面照片 |
| 保真度 | 中保真 | 楼栋位置真实，标志性单体（钟楼 / 八边形楼 / 校门）精建，普通楼体块化 |
| 画面调性 | 写实白天 | 红砖学院风是该校最强识别特征，科技蓝会抹掉它 |
| 交互 | 自动巡览 + 可随时接管 | 大屏多数时间无人值守 |
| 页面入口 | 独立路由 `/school` | 与应急业务互不干扰，不复用 `Head.vue` |
| 数据来源 | 静态数据文件 | 项目现有接口均为应急业务，学校介绍无对应后端 |

## 素材与还原依据

素材：正射卫星影像 2 张、百度地图矢量与 2.5D 轮廓 2 张、建筑与校门实拍照片 6 张、
百度百科词条「成都市实验小学西区分校」。

三条百科记载与卫星影像互相印证，构成场景还原的骨架：

- **「200 米环形跑道围绕着铺设人工草皮的操场」** → 运动场形态与尺寸
- **「全欧式风格的教学楼大气而厚重」** → 红砖 + 白拱窗 + 灰坡屋顶的材质系统
- **「西区占地 30 亩」** → 比例尺标定。场景取 148m × 130m ≈ 28.9 亩

**南校门与入口梯形广场**（依据用户补充的校门正面照、校名牌近照与对平面形态的说明还原）：

入口不是一条直线，而是一个内凹的梯形前广场：门体自沿街围墙线（z=67）后退 10m 至 z=57，
位于梯形的上底；两条斜边由门体两端各向外扩 12m 连回沿街围墙线，下底即朝街的开口；
梯形内为砖红铺装。校名牌嵌在**右侧斜边**的红砖墙上，法线朝广场内侧，
站在门前即可正对读到。斜边的转角与校名牌的定位由 `layout.js` 的 forecourt 参数推出，
改进深或外扩宽度时两者会同步跟随。

门体本身为三段式体量——中央主门高大、两侧次门较低，各段砖墙挖出拱券开口，
外圈套白色拱圈与壁柱，墙脚为灰色石材勒脚，顶部白色檐口（主门再叠一道收分压顶）；
主拱内为对开敞开的铁艺门扇，次拱内为固定铁栅。
大门右侧（自校外看）红砖墙上嵌白色石框 + 深灰绿石材拼板，
阴刻「成都实验小学 西区分校 / Chengdu Experimental Primary School West Campus Branch」，
文字由 Canvas 绘制成贴图，不依赖字体文件或图片素材。

**推断项（未获校方确认，界面上以橙色「名称待确认」标记）**：

1. 八边形建筑标注为「罗马议事厅」——依据百科提及该厅 + 环形议事形制与八边形平面吻合
2. 「俄罗斯图书馆」所在楼栋未能识别
3. 西侧长楼疑为住宿部（百科提及学校设住宿部）

**刻意排除**：百科所载师资名单（陆枋、向尧等）系 2009 年前后内容，人员大概率已变动，
不上大屏以免写错真人。班级数 / 师生数百科未载，界面显示「待补充」，不编造数字。

## 架构

```
src/views/school/
├── index.vue              页面外壳：布局、取数、事件转接
├── components/            纯展示组件（5 个）
├── scene/                 三维逻辑，不含任何 Vue 依赖，可独立调试
│   ├── layout.js          校园总平面常量（唯一数据源）
│   ├── textures.js        Canvas 程序化贴图（零外部素材）
│   ├── materials.js       共享材质 + 立面材质缓存
│   ├── geometry.js        四坡屋顶 / 跑道轮廓 / 地面片等几何工具
│   ├── buildings.js       常规楼栋 + 围墙
│   ├── landmarks.js       钟楼 / 八边形楼 / 校门 / 旗杆景观石
│   ├── playground.js      运动场
│   ├── plaza.js           中轴广场与喷泉
│   ├── vegetation.js      绿化（InstancedMesh）
│   ├── cameraTour.js      巡览状态机 + 自写轨道控制
│   ├── picking.js         射线拾取
│   └── SchoolScene.js     总装、渲染循环、资源释放
└── data/schoolData.js     文案 / 指标 / 地标 / 机位；fetchSchoolData() 为换接口的接缝
```

`scene/` 与 Vue 解耦：三维逻辑可单独调试，`index.vue` 不会膨胀成巨型文件。

## 实现要点

- **坐标系**：米制，X 向东、Z 向南、原点在校园几何中心
- **比例尺标定**：全部坐标由正射卫星影像反推，比例尺约 8.73 px/m，
  换算式 `X = (px - 717.5) / 8.73`、`Z = (py - 737.5) / 8.73`。
  据此量得用地 **130m(东西) × 152m(南北)** = 19760 ㎡ ≈ 29.6 亩，与「占地 30 亩」吻合。
  ⚠ 首版误按「宽 148 × 深 130」建模，长宽比是反的，导致全部楼栋排布错位，
  已按卫星图整体返工。单栋边界仍有 ±2~3m 误差，楼群相对关系与总平面格局可信
- **贴图**：全部 Canvas 现画，无外部图片，配色集中在 `textures.js`
- **立面**：BoxGeometry 材质数组，X 向与 Z 向各用按自身宽度换算重复数的贴图，避免短边拉伸
- **立面分层与分面**：楼身拆成「首层 + 以上楼层」两段，依据内庭实拍照片：
  - 首层为灰色粗琢石材砌的连续拱廊（过道），与上部红砖形成材质对比；
  - 上层并非每一面都是窗墙 —— 翼楼临院一侧是开敞外廊（砖砌立柱 + 白色栏杆 +
    凹进的教室门与门边小窗），连接两翼的横楼才是整面拱窗。
    由 `layout.js` 中每栋楼的 `corridor` 字段指定哪些面走外廊，
    取值对应 BoxGeometry 的材质数组顺序 +X / -X / +Z / -Z
- **贴图重复数的坑**：贴图重复数要按「这张贴图实际铺开的宽度」算。
  BoxGeometry 每个面的 UV 各自 0..1，传该面宽度即可；
  CylinderGeometry 的侧面 UV 是绕整圈走 0..1，必须传整个周长，
  否则开间会被摊到整圈上、横向拉伸成变形的大窗（八边形楼曾踩过此坑）
- **四坡屋顶**：非索引顶点 + `DoubleSide`，规避三角形绕序问题
- **运动场分层**：跑道 / 草皮 / 硬地球场 / 划线铺在依次升高的 Y 上。
  两块地面若同高且区域重叠会产生 Z-fighting 闪烁条纹；内场各块用
  `innerFieldShape` 按跑道内圈裁剪，弧段处自动收窄，不会像矩形那样戳到跑道上
- **中轴水景定位**：水景含两端圆池总长约 41m，需落在两翼楼南端（z=2）到大门
  （z=57）之间的开敞广场内并居中略偏北；中心小于 22 时北端圆池会卡进内院
- **树木避让**：行道树按固定间距批量排布，必然有若干棵落进楼体、跑道或前广场，
  统一用几何判断剔除（`vegetation.js` 中 isInsideBuilding / isOnTrack /
  isInForecourt）。跑道两端是半圆，判断边界要按圆方程收窄而非当作矩形
- **楼栋退距**：所有楼栋收在 X ∈ [-57, 57]、Z ∈ [-68, 68] 之内，
  与围栏线（X ±65 / Z ±76）之间留出至少 8m 绿化带。
  首版按卫星图直接落位时，西侧长楼正压在围栏线上、西南西楼还穿出了围栏外
- **周界围栏**：除正大门外，校园周界与入口梯形斜边全部是铁艺围栏
  （砖基座 + 等距砖柱 + 白色柱帽 + 黑色竖栅），依据校门实拍照片 ——
  并非整圈实心砖墙。周长五百余米、竖栅上千根，全部走 InstancedMesh
  （`fence.js`），每种构件只占一次 draw call
- **教室分布**：外廊贴图的一张图 = 一间教室单元（门 + 两三扇窗），
  不是一个开间。重复次数为「每层教室数」= `round(墙宽 / 11m)`，上限 4 间；
  更长的楼是把每间摊宽而非增加间数。首层拱廊的拱数按「教室数 × 3」取，
  与上层立柱对齐。早先按每个开间放一扇门，45m 的楼一层排出十来个门
- **树木**：照片级树木需要带 alpha 叶片卡的外部模型，与零素材前提冲突；
  交叉 billboard 贴图树在俯视全景机位会露出交叉平面。因此走程序化几何：
  树冠由多个带顶点扰动的不规则球体叠成，逐棵随机种类 / 高矮 / 胖瘦 / 旋转，
  并用 `instanceColor` 做到逐棵绿色不同（用到它的材质基色必须设为白色，
  否则会渲染成白树）
- **开间宽度**：立面 / 拱廊 / 外廊三种贴图共用 `BAY_WIDTH`，保证上下层的
  窗、拱、柱竖向对齐。取 4.2m；早先取 3m 时每层窗户过密、整面墙像幕墙。
  改开间宽度时贴图画布宽度要同比例跟着改，否则窗会被横向拉扁
- **性能**：材质全场景复用、树木 InstancedMesh、像素比上限 1.5、页面不可见时停渲染
- **免登录**：`permission.js` 新增 `PUBLIC_PATHS` 白名单，学校页不走登录校验与百度地图加载

## 总平面返工记录（2026-09-22）

用户比对卫星图后指出建筑排列对不上。逐项复核发现根因是比例尺标定错误
（长宽比颠倒），连带所有要素错位。按卫星图重新量取后修正：

| 项目 | 返工前 | 返工后（卫星图实测） |
|---|---|---|
| 用地 | 148×130（宽>深） | 130×152（深>宽） |
| 建筑布局 | 4 条分散长条 + 南开口 U 形主楼 | 西北侧连续梳齿状楼群（开口朝东）+ 独立主楼居北 |
| 跑道外轮廓 | 40×88，中心 (46,12) | 48×86，中心 (34,20) |
| 八边形楼 | (-34,20) 孤立于草坪 | (-27,23)，西接连接体、东临广场 |
| 中轴广场 | 36m 宽单片米黄铺装 | 22m 窄带；北段米黄（水景所在）+ 南段橙色活动场地 |
| 水池中心 | z=28 | z=4（校园南北中部） |
| 校门 | 居中 x=6 | 偏西 x=-7 |

六个巡览机位随之全部重算。

返工后经用户现场核对，再移除两栋卫星图误读出来的楼：
「西北楼群·北横楼」（北侧西楼以南那条东西向楼）与「议事厅连接体」
（八边形楼西北侧那条南北向窄楼）。楼栋数由 10 降为 8，两处现为绿地。
