# 城市三维总览 · 景点人流 设计文档

日期：2026-09-29
状态：已实现（2026-09-29 验收，实现记录见文末）
前置：`2026-09-28-city-landmarks-design.md`（景点精细建模，已实现）

## 目标

巡览镜头切到某个景点后，在该景点的步行空间里出现一群微缩小人，沿路径走动，
让画面有「人气」。风格与景点一致：低多边形、饱和配色、圆润可爱。

## 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 何时出现 | 飞抵站点时在该站生成，离站 / 回总览时淡出并回收 | 同时只活跃一站，性能可控；总览尺度下小人本来就看不见 |
| 尺度 | 插画式放大到 4 m 身高（真人约 1.7 m；初版取 3 m，实现后上调） | 到站距离 300～720 m，1.7 m 只有 4～7 像素；3 m 在到站距离只有约 7 像素、只是彩色小点，4 m 约 10 像素，头、身、腿分得开；4.5 m 时巷道边的人头会碰到宽窄巷子檐口与人民公园茶廊廊檐，故取 4 m |
| 造型 | 头（球）+ 身体（圆台）+ 两条腿，腿随步频前后摆，身体轻微上下起伏 | 最少构件就能读出「走路」；远处主要靠移动与摆腿感知 |
| 渲染 | 全城共用一套 InstancedMesh（身体、头、左腿、右腿 4 个），上限 240 人；衣服、裤子、肤色、发色按实例着色 | 4 次 draw call；每帧只更新当前站的实例矩阵 |
| 路径来源 | 各景点模块在 build 结果里新增 `walkways`（步行路径） | 路径只有景点模块最清楚（巷道、中轴、屋顶花园、桥面） |
| 阴影 | 小人不投影（`userData.animated`），接收阴影 | 阴影贴图是静态的 |
| 确定性 | 生成用固定种子随机 | 每次到站画面一致，便于验收 |
| 减少动态 | `prefers-reduced-motion` 时小人站立不动 | 与巡览的减少动态处理一致 |

## 接口

### 景点模块新增字段

```js
walkways: [
  {
    points: [[x, z], ...], // 世界坐标折线（或闭合环）
    y: 1.0,                // 路面高度（米）
    width: 6,              // 可走宽度（米），小人在中线两侧随机偏移
    closed: false,         // true 时为环路，小人循环走；false 时走到端点折返
    density: 1             // 相对密度（每 100 m 路径约 density × 4 人），默认 1
  }
]
```

每个景点 1～6 条路径，总长度决定人数（每站 40～120 人，受全局上限约束）。

### crowd 模块 `src/views/city/scene/crowd.js`

```js
createCrowd(theme, { max = 240, reduceMotion = false }) → {
  group,                  // 加入场景
  show(walkways, seed),   // 在给定路径上生成人群并淡入（按路径长度与 density 分配人数）
  hide(),                 // 淡出后回收
  update(dt),             // 每帧推进：沿路径前进、折返、摆腿、起伏、淡入淡出
  dispose()
}
```

- 每个人：路径索引、沿路径弧长位置 s、方向（±1）、速度（真人 1.1～1.8 m/s 按身高 × 4 / 1.7 放大为 2.7～4.3 m/s，
  步态频率 v / (0.9h) ≈ 0.75～1.2 次/秒）、
  横向偏移（±width/2）、步频相位、配色。
- 朝向：沿路径切线方向（折返时平滑转身 0.4 s）。
- 淡入淡出：用实例缩放从 0 到 1（0.6 s），避免透明排序问题。
- 小人互不避让（远景下看不出），但横向偏移与速度随机，避免排成一队。

### 接入

- `createLandmarks` 汇总 `walkwaysBySpot[i]`。
- `CityScene`：`onArrive(i)` → `crowd.show(walkwaysBySpot[i], seed = i)`；`onStopChange` 离站、`gotoOverview` → `crowd.hide()`；`_loop` 里 `crowd.update(dt)`；`dispose` 释放。
- lab 页：景点模式默认显示该景点人群（`people=0` 关闭），渲染前先推进 3 秒，让小人散开、姿态不一；截图时即为「走动中」的一帧。

### 尺度调整

- 身高 3 m → 4 m：到站机位 300～720 m、俯角约 40° 时，3 m 只有 6～8 px，是彩色小点；
  4 m 约 8～11 px，头、身、腿分得开。4.5 m 会让宽窄巷子巷边行人头顶碰檐口、人民公园茶廊廊檐。
- 速度按身高同比放大为 [2.7, 4.3] m/s（真人 1.1～1.8 m/s × 4 / 1.7），步频保持真人水平；
  perMeter 不变，各站人数不受影响。
- 造型比设计多一片发片，共 5 个 InstancedMesh（body、head、hair、legL、legR），
  body / head / hair 共用一份实例矩阵，每人 102 个三角形。

### 与计划的偏差

- **合江亭**：廊桥木廊芯体是实心的，只走柱列（z = ±3.9）与桥面石栏之间的外侧边道
  （z = ±5.6、宽 0.8，端点折返）：上层桥面东西两侧各一段贯通主楼（各约 36 m），
  两端下层桥面沿端楼各一段（4 段各约 16 m）；主楼、端楼底层腰檐下沿离桥面约 4.6 / 4.5 m，
  高过最高个体头顶 4.35 m，小人从檐下走过。上下层之间的斜坡段不走，所以没有走「桥面全长」
  （2026-09-30 廊桥按照片细化后重定；此前只走两段长廊下的 4 段各约 17 m 边道）。
- **文殊院**：塔台南侧紧贴一栋廊房，塔周路无法闭合，改为绕塔北、西、南的 255° 圆弧
  （半径 11 m，140°→395°），两端折返。
- **成都 IFS**：红星路一侧前场没有铺装，人行道高度取地面 `GROUND_Y`（−0.5），不是计划里的 0.9。
- **天府广场**：外沿低台阶实心板按下沉广场开口挖洞，下沉广场恢复约 1.2 m 深，环路回到
  `SUNKEN.floor`；北线宽 5 → 4.2，避免贴边小人身体擦进草带。
- **宽窄巷子**：可走宽度不是简单的「巷宽 − 1.5」，而是按两侧障碍（檐下灯笼、文化墙灯笼、
  宽巷子行道树树干）加身体半径逐侧扣除。
- **短段门槛**：被树冠或殿堂断开后短于 15 m 的零碎段丢弃（IFS 屋顶小径、太古里大慈寺甬道、
  文殊院中轴甬道），免得几个人在几米长的路上来回折返。
- 圆角环路（每角 4 段 22.5° 圆弧）抽到 `landmarks/kit/walkways.js` 的 `roundedLoop` 共用。

### 校验方法

Node 独立校验脚本（不依赖景点模块自己的判断），对每条路径：

1. **逐点采样**：沿中线每 0.5 m、横向每 0.25 m（覆盖 ±width/2）取点，求该点所有支撑面
   （地面 −0.5、绿地 0.2、水面 0.3、河 0.35、路缘 0.5、路面 0.6+、全部景点三角形），
   可走带内最高支撑面须与路径 `y` 相差不超过 0.06 m，且不是水面；不在保留楼轮廓内。
2. **头顶净空**：`y + 0.25` 到 `y + 4.35`（4 m × 最大个体倍数 1.08）之间不得有景点三角形，
   通用树树干（1.2 m 内）与低垂树冠也算遮挡。
3. **分部件净距**：腿（0.25～1.56 m）、身体（1.56～3.11 m）、头（3.11～4.35 m）三个高度带，
   可走带边缘到障碍的水平距离分别不小于 0.63 / 0.86 / 0.52 m；开放路径端点再沿路径方向外探 1 m。

验收时的结果（`HEAD = 4.35`、`BODY = 0`）：

| 景点 | 坏点 | 说明 |
|---|---|---|
| 天府广场 | 360 | 全部是 S 形分界带（高出铺装 0.2 m 的浅金白细条）被散步线与金盘外环横穿，属设计取舍，远景看不出 |
| 春熙路·太古里 | 0 | 头部带最近 0.90 m（檐口） |
| 成都 IFS | 11 | 小径端面与拐角外侧个别采样落在草皮上（低 0.2 m），脚底最多悬空 0.2 m，远景不可见 |
| 宽窄巷子 | 0 | 头部带最近 0.90 m（檐口）、身体带 0.90 m（灯笼） |
| 人民公园 | 96 | 全部是碑台外环路横过 0.15 m 高的分隔条；茶社院内头部带净距 0.55 m（需 0.52） |
| 文殊院 | 0 | — |
| 合江亭 | 0 | 桥面边道腿部带净距 0.67 m（需 0.63，桥面石栏）、身体带 0.985 m（需 0.86，端楼腰檐翼角），头顶净高 ≥ 4.51 m（2026-09-30 廊桥细化后复跑） |

### 城市页验收

`#/city?spot=0..6` 1920×1080 无头 Chrome（SwiftShader 软件渲染）：到站后暂停巡览，
冻结动画循环、按虚拟时间推进 1 s 连拍两帧。7 站两帧之间全部行人都有位移，平均 3.3～3.5 m
（与速度区间一致），控制台无报错。离站：人数在飞往下一站途中归 0，飞抵后生成下一站人群；
点「复位到总览」后人数归 0、总览画面无残留。

### 性能

- `crowd.update`：人数最多的太古里 90 人，Node 1000 帧平均约 29 µs/帧（设计目标 < 1 ms）。
- 渲染：人群新增 5 次 draw call（设计估计 4，多出的是发片），每人 102 个三角形；
  到站时整帧 23～27 次 draw call、76～79 万三角形，其中人群 4.6k～9.2k 三角形。

### 已知限制

- 校验只能按水平采样看到竖直面的投影（距离 < 0.08 m 视作命中），看不到很薄的竖直构件的全部情况，
  最终仍以截图为准。
- 人民公园茶社院内头部净距的余量只有 2～3 cm，合江亭桥面边道腿部净距余量约 4 cm（桥面石栏），改动这两处模型时需复跑校验。
- 合江亭廊桥细化后为 57 人（原 45 人，曾是离每站 40 人下限最近的一站）。
- lab 页不画通用树，lab 截图里看不到树冠遮挡；树冠与路径的关系只在城市页与校验脚本里体现。
- 站点机位是斜俯视：宽窄巷子窄巷、太古里里巷的行人有一部分被屋面挡住，人民公园园路大半在树冠下，
  画面上可见人数少于实际人数。
- 小人互不避让，偶尔几个人叠在一起走一段（如合江亭河岸步道、台基环路），属设计取舍。
- 已修复：`crowd.update(0)` 曾会取消 `hide()` 的淡出、或把刚 `show()` 的人群清空；
  现在淡入淡出只在 dt > 0 时推进。
