# 城市三维总览大屏 设计文档

日期：2026-09-28
状态：已确认，待实施

## 背景与目标

在大屏项目中新增一个「城市 3D」页面：用真实地图数据还原成都市中心的三维街区，
配合城市总览指标与主流景点介绍，形成一块可无人值守自动巡览、也可随时接管操作的展示大屏。

与现有应急指挥业务完全独立，与 `/school` 页面同一套接入模式。

## 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 三维形式 | 纯 three.js，不用地图 SDK | 用户明确要求；不依赖百度 ak 与外网地图服务 |
| 地图来源 | OpenStreetMap 真实数据（建筑轮廓 / 道路 / 水系 / 绿地） | 街区、楼体位置、锦江河道真实；可换城市 |
| 楼高 | 有 `height` / `building:levels` 标签用真实值，其余按建筑类型估算 | 市中心范围内仅约 10% 建筑带高度标签 |
| 画面调性 | 缤纷插画风 | 用户在深色科技风、明亮素雅风、缤纷插画风三版效果图中选定 |
| 视角 | 小视场角（30°）近等轴测俯视 | 贴近插画风参考图的俯视感 |
| 交互 | 自动巡览 + 可随时接管 | 大屏多数时间无人值守 |
| 页面入口 | 独立路由 `/city`，加入 `PUBLIC_PATHS` | 免登录、不加载百度地图，与应急业务互不干扰 |
| 数据来源 | 几何数据为预处理静态 JSON，业务数据为静态文件 | 无对应后端；`fetchCityData()` 是换接口的唯一接缝 |

## 效果图结论（原型验证）

实施前用同一份真实数据做了三版原型渲染并截图确认，结论直接沿用：

- 范围：经度 104.045–104.095、纬度 30.640–30.678（天府广场周边约 4.8km × 4.2km），
  建筑 7079 栋、道路 1035 条、水系 43 面 + 河流 12 线、绿地 94 面
- 坐标：以天府广场（104.0657, 30.6574）为原点的等距圆柱投影，
  `x = (lon − lon0) × 111320 × cos(lat0)`，`z = −(lat − lat0) × 110540`，单位米，X 向东、Z 向南
- 挤出后底部顶点的 y 会有 −1e-14 量级浮点误差，做分数次幂前必须钳到 0，否则得到 NaN、楼面变黑
- `ExtrudeGeometry` 会自行统一轮廓绕序，OSM 点序方向不需要预处理
- 色调映射用 `NeutralToneMapping`，ACES 会把高饱和色压灰

## 视觉规格（缤纷插画风）

集中写在 `scene/theme.js`，调色只改这一个文件。

| 要素 | 规格 |
|---|---|
| 背景 | 暖白 `#f6f3ec`，无雾 |
| 地面 | 暖米色 `#efe9dd` |
| 绿地 | 翠绿 `#9bd45e` |
| 水系 / 河流 | 湖蓝 `#3ec6df`，粗糙度 0.35 略带反光；河流按 48m 宽带状挤出 |
| 道路 | 白色路面 + 淡灰路缘，四档宽度：主干 18/24、次干 12/16、支路 8/11、街巷 5/7（路面/路缘，米） |
| 矮楼（< 24m） | 六色暖色盘随机（米白、浅桃、浅灰、浅蓝灰等），屋顶提亮 30% |
| 中楼（24–55m） | 四色灰白 / 浅蓝盘随机 |
| 高楼（≥ 55m） | 蓝色玻璃，底 `#3d86d0` → 顶 `#8fd0f2` 渐变 |
| 窗格 | 着色器按世界坐标绘制：竖向 3.6m、横向 3.4m 一格；玻璃楼为明暗玻璃条带，普通楼为淡淡窗格；屋顶不画 |
| 树木 | 低多边形（二十面体树冠 + 圆柱树干），四种绿 + 22% 金黄；公园内按面积随机撒点、河岸两侧每 34m 一棵 |
| 光照 | 半球光 1.45 + 暖白太阳光 2.6，单光源软阴影，阴影贴图 4096 |
| 景点标注 | 橙色圆球落点 + 白色圆角标签牌（当前站加青绿描边） |
| 界面 | 白色圆角卡片、青绿强调色 `#2f8f96`、深灰文字 `#1f2d3a` |

## 架构

```
src/views/city/
├── index.vue                 页面外壳：布局、取数、事件转接
├── components/
│   ├── CityHead.vue          顶栏：标题、日期时间、天气文案
│   ├── OverviewPanel.vue     城市总览：四项指标 + 城市标签
│   ├── FlowPanel.vue         热门景点客流 Top5 条形
│   ├── SpotPanel.vue         景点介绍：图位、名称、简介、四项键值
│   ├── TourBar.vue           底部景点导览条
│   ├── MapTools.vue          右侧工具栏：复位视角 / 放大 / 缩小 / 全屏 / 巡览开关
│   └── Compass.vue           指北针（随相机方位旋转）+ 比例尺
├── scene/                    三维逻辑，不含任何 Vue 依赖，可独立调试
│   ├── theme.js              全部视觉参数（颜色、尺寸、光照、相机限制）
│   ├── projection.js         经纬度 ↔ 米制局部坐标
│   ├── terrain.js            地面、绿地面、水系面
│   ├── roads.js              折线挤成带状面（道路、河流共用）
│   ├── buildings.js          轮廓挤出、分档配色、窗格着色器注入、合并为单 Mesh
│   ├── trees.js              撒点算法 + InstancedMesh
│   ├── markers.js            景点落点球 + CSS2D 标签
│   ├── cameraTour.js         巡览状态机 + 轨道控制（沿用 school 页思路重写，支持 30° 视场角与米级尺度）
│   ├── picking.js            楼体射线拾取
│   └── CityScene.js          总装、渲染循环、resize、资源释放
└── data/
    └── cityData.js           城市指标 / 标签 / 客流 / 景点；fetchCityData() 为换接口的接缝

public/city/chengdu.json      预处理后的几何数据（buildings / roads / water / parks / rivers）
scripts/fetch-osm-city.py     从 Overpass 拉取并预处理成上述 JSON；换城市或范围时重跑
```

`index.vue` 通过 `fetchCityData()` 取业务数据、通过 `fetch("/city/chengdu.json")` 取几何数据，
两者都到位后再实例化 `CityScene`。生产环境 `base` 为 `/bi/`，几何数据路径要经
`import.meta.env.BASE_URL` 拼接。

## 数据

### 几何数据 `public/city/chengdu.json`

```
{
  "meta":      { "city": "成都", "origin": [104.0657, 30.6574], "bbox": [...] },
  "buildings": [{ "p": [[x, z], ...], "h": 24.5, "n": "楼名或 null" }],
  "roads":     [{ "p": [[x, z], ...], "c": "a|b|c|d" }],
  "water":     [[[x, z], ...]],
  "parks":     [[[x, z], ...]],
  "rivers":    [[[x, z], ...]]
}
```

- 坐标保留一位小数，体积约 1MB，gzip 后约 250KB，随构建产物一起发布
- 道路分档 `a` 主干（motorway / trunk / primary 及其 link）、`b` 次干（secondary）、
  `c` 支路（tertiary）、`d` 街巷（residential / unclassified）
- 楼高估算：`height` 标签优先，其次 `building:levels × 3.3`，
  否则按类型区间用建筑 id 做种子随机（apartments 30–70、commercial 24–60、
  office 40–90、residential 18–45、house 6–9、school 12–18 等），保证每次生成一致

### 业务数据 `data/cityData.js`

- `CITY_INFO`：名称、副标题、天气文案占位
- `METRICS`：市域面积、常住人口、地区生产总值、市辖区数（示意值，界面不标「真实」）
- `TAGS`：国家中心城市、历史文化名城、公园城市首提地、世界美食之都
- `FLOW`：热门景点客流 Top5（示意值）
- `SPOTS`：7 个景点，每项含 `name`、`en`、`lon`、`lat`、`desc`、`facts`（四项键值）、
  `cam`（相机相对景点的偏移与距离），首版：天府广场、春熙路·太古里、成都 IFS、
  宽窄巷子、人民公园、文殊院、合江亭
- 景点实景图为占位渐变块，用户提供图片后替换 `image` 字段即可

## 交互

- **自动巡览**：按 `SPOTS` 顺序飞往各景点，飞行 2 秒（easeInOutCubic），停留 8 秒；
  停靠时通过回调通知页面切换右侧景点面板与底部导览条高亮
- **接管**：拖动旋转、滚轮缩放、点击楼体任一操作立即暂停巡览；15 秒无操作自动恢复
- **导览条 / 工具栏**：点击导览条直接飞往该景点；工具栏可复位到总览机位、放大缩小、
  切换全屏（`screenfull`）、开关自动巡览
- **点击楼体**：射线拾取命中建筑后高亮该楼（临时改顶点色或叠加描边）并在其上方显示
  小气泡：名称（无名则显示「建筑」）与估算高度；再次点击空白处取消
- **相机限制**：俯仰角 20°–80°，观察距离 300–6000m，注视点限制在数据范围内
- **页面不可见时停止渲染**（`visibilitychange`），大屏切页不空耗 GPU

## 错误处理

- 几何数据请求失败：场景区显示「城市数据加载失败」并保留面板，控制台输出原因
- 浏览器不支持 WebGL：显示「当前浏览器不支持三维展示」提示
- 单栋建筑轮廓少于 3 个点或挤出异常：跳过该栋，不影响整体

## 性能

- 全部建筑合并为一个 `BufferGeometry`，道路按档合并，树木 `InstancedMesh`
- 像素比上限 1.5；阴影仅太阳光一盏
- 预期规模：建筑约 30 万三角形、树木约 3–6 千棵，目标在大屏机器上稳定 60fps
- 建筑合并与撒树在 `CityScene` 构造时同步完成，首帧前显示「城市场景构建中」

## 验证方式

项目无测试框架，采用：

- `yarn lint:eslint` 通过
- 用无头 Chrome 对 `/city` 页面截图（总览机位与天府广场特写）与效果图比对
- 在内置浏览器中验证：巡览切换、接管与恢复、导览条跳转、楼体点击、工具栏、全屏

## 暂不包含

- 手工建模的地标（合江亭亭子、IFS 熊猫、锦江游船）：后续以 glTF 资产放在景点坐标上
- 后端接口、实时数据
- 其他城市（脚本已支持，但需重新拉数并核对景点坐标）
- 标签避让：首版标签可能在个别机位重叠，后续按需处理
