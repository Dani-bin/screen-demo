# 智能矿山（West Elk 煤矿）设计稿

2026-10-17。用户要做煤矿可视化平台，想看真实地形沙盘能做到多真实，让我找一个国外矿山做演示，先出设计稿。

## 选矿：West Elk 煤矿（美国科罗拉多州 Somerset）

| 项 | 内容（公开资料） |
| --- | --- |
| 运营方 | Mountain Coal Company（Arch Coal 子公司；Arch 与 CONSOL 2025 年合并为 Core Natural Resources） |
| 开采方式 | 井工，长壁综采 + 连采掘进，后退式回采 |
| 煤层 | 先后开采 F、E、B 煤，2025 年第四季度转入 B 煤；地层向北北东缓倾 3–5°，最大埋深约 1,600 ft（≈ 490 m） |
| 规模 | 井田约 74.5 km²，2025 年产 294 万 t，职工 292 人 |
| 地面 | 北福克河谷里的工业广场（选煤厂、储煤场、铁路装车站，Union Pacific），南面山上有大量地面瓦斯抽采钻场 |

选它的理由：

1. **和国内煤矿平台关心的东西对得上**：井工长壁开采，有巷道、工作面、采空区，瓦斯大（州内最大的单一甲烷排放源），地面打抽采钻孔、上火炬，正好覆盖通风瓦斯、综采、人员这些专题。
2. **地形像参考图**：河谷加山地，12 × 10 km 范围内海拔 1,785–2,758 m，落差近千米。
3. **数据是公有领域**：USGS 3DEP 激光雷达高程（1 m）和 USDA NAIP 航拍（0.3 m）都是美国联邦政府数据，演示随便用，没有 Google / Esri 影像的授权问题，还能按任意范围直接导出。

备选：SUFCO（犹他州，长壁，峡谷地形）、Twentymile（科罗拉多州，长壁）、Hambach（德国，露天褐煤）。

## 哪些是真的，哪些是示意

| 真实数据 | 示意 / 演示数据 |
| --- | --- |
| 地形（3DEP 1 m 激光雷达 DEM，全景重采样到 10 m 网格、近景 2 m） | 各地层厚度与间距、B 煤面的绝对标高 |
| 影像（NAIP，全景 1.5 m / 像素、近景 0.5 m / 像素） | 工作面编号、尺寸、开采顺序与进度 |
| 工业广场各设施、主平硐、Deer Creek 回风井的位置（按 0.5 m 影像判读） | 巷道走向（主平硐 → 暗斜井 → 南翼大巷 → 东翼工作面） |
| 85 个抽采钻孔的位置：从影像里自动识别的林中钻场（共 878 处），取落在工作面上方的 | 传感器读数、产量、人员、告警等全部面板数字 |
| 地层顺序与煤层名（USGS PP 1625-B、科罗拉多地调局 RS-36）、倾向与倾角 | |
| 矿井概况面板里的面积、产量、职工、埋深 | |

工作面走向是推断出来的：影像里的钻场大致按东西向成排、行距四五百米，地面抽采钻孔一般沿工作面打，所以示意工作面取东西走向、南北依次排开（宽 320 m，中心距 400 m，长 2.7–3.4 km）。埋深按地形逐面检查过（东翼 250–720 m）。

## 版式

整屏 1920 × 1080，深海军蓝底、青色强调，标题阿里妈妈数黑体、正文思源黑体、数字 DIN（与其他 demo 一致）。左右各 404 px 半透明面板，中间是悬浮的地形沙盘，底部是专题切换。

- **综合态势**（01）：东北方向俯视（方位 50°、俯角 34°）。地表保留航拍原色，只按坡向补一点明暗、远处加空气透视。地下采区按状态投影到地表：采空区淡紫、在采橙、待采 / 规划青色虚线；抽采钻场是黄绿色光点。沙盘侧壁按倾斜煤层面算出地层上色，不是把影像往下拉伸。
  左：矿井概况 / 生产统计（近 7 日产量）/ 煤流运输；右：安全监测 / 瓦斯抽采（在抽率、回风隅角 24 h 曲线及预警线和断电线）/ 告警事件。
- **井下透视**（02）：地表变成半透明灰蓝色并叠等高线，远端侧壁内侧压暗，像剖开的盒子。B 煤面上画采空区（斜线填充）、在采工作面（发光的面）、待采 / 规划面；巷道按进风蓝、回风红、斜井黄着色；抽采钻孔是从地面到采空区上方的竖线；回风隅角 T1 是黄色预警点。
  左：综采工作面（推进、182 架液压支架、采煤机位置）/ 地层柱状（按工作面处的真实地表高程算埋深）/ 采掘接续；右：通风系统 / 瓦斯监测 / 人员定位。
- **工业广场近景**（03）：只有顶栏和标注，验证拉近后的效果。

## 真实感结论（回答「能做到多真实」）

- **全景沙盘（12 km）**：只用 DEM 加航拍，就能做到参考图 1 的效果，山体、河谷、道路、钻场都清楚。
- **近景（3 km）**：1 m 高程加 0.5 m 影像依然清晰，皮带走廊、储煤场、水池、厂房都看得清。但 3DEP DEM 是去掉地物的地面高程，**建筑和设备都是贴在地上的**，越往近拉越明显。要立体，就得给关键建筑单独建模（同 `/charging` 的 Blender 流程），或者改用激光雷达的首次回波表面（DSM）。
- **国内项目**：没有 3DEP 这样的免费 1 m 数据，公开高程只有 12.5–30 m。想要近景达到这个程度，要用矿方的无人机航测或倾斜摄影。

## 生成流程

```bash
python scripts/smart-mine/fetch_data.py    # 下载 DEM + 影像到 models/smart-mine/raw/（需 numpy、Pillow；要联网）
python scripts/smart-mine/prepare.py       # 重采样高程、识别钻场、生成布局 → models/smart-mine/render/（设计稿）与 public/smart-mine/、src/views/smart-mine/data/（页面）；另需 scipy
```

然后起开发服务器（`.claude/launch.json` 的 `bi-demo`，或 `DEV_HTTP=1 PORT=8893 yarn dev`），打开 `/docs/design/smart-mine/drafts-source.html?frame=overview|underground|closeup`（`?clean=1` 去掉面板，`?cam={"az":50,...}` 临时改镜头），截图：

```bash
node scripts/smart-mine/capture.mjs "http://localhost:8893/docs/design/smart-mine/drafts-source.html?frame=overview" docs/design/smart-mine/01-overview.png
```

注意：

- `models/` 整个目录被 git 忽略，换机器要重新跑上面两个脚本。
- vite 会把 HTML 里内联 `<style>` 的 px 转成 rem（项目的 pxtorem 规则），设计稿会被缩成 160 px 宽，所以样式放在 `*.no-convert.css` 里。
- 近景俯角超过约 42° 时，无头 Chrome 截图会卡在 `Page.captureScreenshot`（内置浏览器里正常），设计稿近景取 40°；截图脚本限时 20 s 并重试一次。

## 实现（2026-10-17）

设计稿方向确认后做成了 `#/smart-mine`（已加入首页 `demos.js`）。代码在 `src/views/smart-mine/`：

| 部分 | 内容 |
| --- | --- |
| 数据 | `public/smart-mine/`：高程 PNG（16 位拆进 R / G 两个字节，5 cm 精度）+ webp 影像，全景 4096 px、近景 6000 px，共约 8.6 MB；`data/layout.json` 为布局。都由 `prepare.py` 生成 |
| 场景 | `scene/MineScene.js`：两块地形（近景首次进入时才加载）、专题镜头补间、空闲摆动、标注投影；`terrain.js`：地表 / 侧壁 / 剖切面 / 地台；`underground.js`：井下物体与动画；`theme.js`：配色与五个专题的镜头 |
| 仿真 | `sim/simulator.js`：按矿区当地时间（山地时区）推算。两个生产班割煤、夜班检修；日产约 1 万 t；采煤机单程 4 分钟（演示加速）；回风隅角瓦斯随割煤升高，接近 0.8% 预警线时出告警 |
| 页面 | 五个专题（综合态势 / 井下透视 / 工业广场 / 通风瓦斯 / 生产运营），各配一组面板；左下工具条切换地表 / 透视 / 剖切 / 复位；标注可点（工作面 → 井下透视，工业广场 → 近景，回风井 / 钻场 → 通风瓦斯） |

和设计稿相比的新增：

- **剖切**（设计稿没出这一帧）：裁剪面从北边缘扫到在采工作面中线，切面跟着走。切面上按地层上色，B 煤带上画出实体煤、采空区、其上约 50 m 的垮落带和 150 m 的裂隙带、发光的工作面和巷道断面。同时地表变透视，越过切面顶部能看到南侧的工作面与钻孔。
- **动画**：巷道里的亮条按风流方向流动（进风蓝、回风红，通风瓦斯专题下更密更亮），抽采钻孔的虚线向上流动，采煤机沿工作面往返，预警测点外圈有扩散光环，井下人员缓慢游走，还有 LW-B07 掘进头。
- **通风瓦斯专题**：镜头拉近在采工作面，标签换成风流路线上的关键点（工作面风量、T1 / T2 测点、回风井负压、大巷进风量）。

已知限制：

- 建筑与设备还贴在地面上（DEM 是去掉地物的地面高程）。工业广场的选煤厂、装车站、皮带走廊、井口还没有单独建模。
- 无头 Chrome 走 GPU 截工业广场近景（俯角大于约 42°）时，`Page.captureScreenshot` 会卡住，内置浏览器里正常（60 fps）。截这个专题要用 `CHROME_FLAGS="--use-angle=swiftshader" node scripts/smart-mine/capture.mjs "<地址>/#/smart-mine?view=plant" <png> --page --settle 20`。SwiftShader 每帧很慢，gsap 会平滑掉卡顿，镜头和淡入动画因此走得很慢，所以等待要给足。
