# 标题、描述、话题、README

## 发布文案.txt（模板 `templates/发布文案.txt`）

**【标题】**四选一，**每个 ≤ 30 字**（抖音标题框的上限），推荐第 1 个，且和开头口播、封面标题一致（同一个钩子说三遍，观众从封面点进来不会觉得货不对板）。四个标题换不同的角度：

1. 开头口播的原句或变体（推荐）
2. 带具体数字 / 结果的
3. 痛点问句（"拿着检查单找不到科室？"）
4. 第二个看点或人群（"腿脚不方便也不怕……"）

标题里"AI"和数字用半角，不加话题标签，不用"震惊""绝了"这类词。

**【描述】**四段：

1. 痛点一句 + 一个表情（🏥 🐑 ⚡ 🏡，和题材相关，全文最多 2 个表情）。
2. 做了什么、看点是什么：把口播展开说，可以补口播里没时间说的一两个具体数字（数字来自页面）。
3. 评论区提问（和口播结尾同一个问题）+ 👇。
4. 空一行，**技术栈**：一行箭头串起来（AI 生图定风格 → AI 通过 MCP 操控 Blender 建模 → Three.js 实时渲染 → Vue 3 大屏 ……，按这个 demo 实际用到的写），句末注明"XX 为虚构，数据为模拟"（真实的部分如实说："地形和卫星影像为真实公开数据，牧场为虚构"）。

**话题**：7–9 个，放在最后一行。固定的几个：`#AI编程 #数字孪生 #三维可视化 #Threejs #可视化大屏 #前端开发`，再加 2–3 个题材词（`#智慧医院 #院内导航`、`#智慧牧场 #草原`）；用了 Blender 加 `#Blender`。

**【封面】**写明上传哪张：`cover-3x4.png`（竖版，抖音推荐）/ `cover-4x3.png`（横版）。

有第三方模型时（Sketchfab CC BY 车辆等），描述末尾加一行署名（见 /charging 的 `MODEL_CREDITS`）。

## douyin 目录的 README.md（模板 `templates/README.md`）

写给以后的自己和用户：

- 一句话说开头 3 秒拍什么、开头口播是什么（用户亲自定的句子注明）。
- **"视频和字幕分开交付"**：成片只有画面，字幕单独 `.srt`。
- 文件表：成片（分辨率、帧率、实际时长）、字幕（条数）、口播、发布文案、封面、`clips/`、`stills/`、分镜脚本。
- 分镜与口播表（时间 / 分镜 / 画面 / 口播），时间用实际成片的。
- 重新生成的命令（录屏、组装、封面），注明录屏要在沙箱外、开发服务器开着。
- 剪映操作：
  1. 拖入成片（想加转场就拖 `clips/` 里的片段）。
  2. 「文本」→「本地字幕」导入 `.srt`；全选字幕 →「文本朗读」生成配音，语速 1.1 倍左右（按 video.json 的 `rate`：5 字/秒 ≈ 1.1 倍，4.4 字/秒 ≈ 1.0 倍）。
  3. 配乐建议（风格、音量 15% 左右）和要卡重拍的时刻（招牌效果高潮那一帧）。
  4. 配音和画面个别地方对不齐时，拖一下那条字幕或那段片段。
- 有隐私顾虑的地方（真实地名、人名）提醒发布前打码。
